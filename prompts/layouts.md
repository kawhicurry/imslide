# 排版目录与适用场景

本目录覆盖当前项目开放的布局入口，以及建议模型选择的26种静态构图。HTML/CSS可组合出更多构图，不存在有限的“所有排版方式”。以下名称不是新的layout参数。

## 当前布局入口

| layout | 适用场景 | 注意事项 |
|---|---|---|
| default | 正文、自定义grid/flex、图表与大多数构图 | 默认已有内边距，勿重复叠加 |
| cover | 封面、短标题与副标题 | 不放密集正文 |
| center | 单句结论、短引文、单指标 | 长中文正文不居中 |
| section | 章节分隔、叙事转折 | 不机械为每个小主题加一页 |
| two-cols | 两个同权重内容对比 | 用::right::分隔，不是所有双栏都适合等宽 |
| image-left / image-right | Slidev原生图文页 | 工具缺少image配置，当前用default+HTML替代 |

其他Slidev布局即使上游存在，也不要传入当前工具。科技风使用整页深色tech-canvas背景，在其内部完成下面的构图。

## 构图选择表

| 构图 | 实现方式 | 适用场景 | 排版要点 |
|---|---|---|---|
| 封面主视觉 | cover / default | 主题开场、产品发布 | 一个主标题、短副标题和一个视觉焦点 |
| 章节分隔 | section / center | 叙事转折、进入新议题 | 章节名与一句承上启下的话 |
| 单句结论 | center / default | 核心主张、转场、收束 | 一句结论加最少的解释；不承载长正文 |
| 标题＋短列表 | default | 要点概览、检查清单 | 3–5项短句，最多两级；避免连续多页列表 |
| 等宽双栏 | two-cols | 前后对比、两个方案、收益与风险 | 同口径、同层级；用::right::分隔 |
| 非对称双栏 | default＋grid | 主论据与补充说明、主图与旁注 | 约2:1或1:2；主次明显而非强行均分 |
| 上结论下证据 | default＋grid | 分析汇报、实验结果 | 标题横贯顶部，下方只放支持它的证据 |
| 左文右图／左图右文 | default＋grid | 案例、人物、产品说明 | 只用有来源图片；图片保持比例，文字不挤进图片 |
| 全幅图片＋叠字 | default＋整页容器 | 情境开场、情绪或场景表达 | 可靠图片加遮罩保证对比；没有图片不编造URL |
| 大数字／单指标 | default / center | 关键成果、规模、变化量 | 数字附单位、时间、基线和来源；不孤立放大数字 |
| 指标带＋主图 | default＋grid | 经营看板、验证结果 | 2–3个相关指标配一张主图；避免仪表盘堆砌 |
| 单图表＋结论注释 | default | 趋势、分布、类别比较 | 清晰单位和图例；静态图或HTML条形图，重点直接标注 |
| 精简比较表 | default＋Markdown表格 | 方案选型、实验基线、规格对比 | 只留影响判断的行列；长表不靠缩字号硬塞 |
| 横向步骤流程 | default＋flex / Mermaid | 流程、方法、操作步骤 | 3–5步顺序清晰；分支太多改架构或泳道 |
| 纵向时间线 | default＋grid | 历史、项目里程碑、研究进程 | 时间顺序与关键事件，避免一条线塞满全部细节 |
| 泳道／责任分工 | default＋grid | 跨团队协作、交接与责任边界 | 按角色分行、阶段分列，区分动作与交付物 |
| 分层架构 | default＋grid / Mermaid | 技术系统、组织层级、能力分层 | 层级和依赖明确；不把无依赖的项连成流程 |
| 中心辐射／关系网络 | default＋Mermaid | 生态、角色关系、概念联系 | 中心主题与少量节点；过密时按子问题拆解 |
| 矩阵／四象限 | default＋grid | 优先级、定位、权衡 | 两轴含义和方向明确；不伪装成精确量化 |
| 漏斗／递进层级 | default＋静态HTML | 筛选、转化、论证层次 | 层宽有数据含义时遵守比例，否则注明示意 |
| 2×2信息组／少量卡片 | default＋grid | 4个并列维度、独立功能 | 仅用于真正并列信息，不将整套稿都套卡片 |
| 问题—原因—行动 | default＋分区 | 复盘、诊断、改进方案 | 明确因果证据，推测原因标为假设 |
| 引文／人物故事 | default / center | 人文叙事、用户声音、观点引入 | 短引文注明来源；具体场景不编造细节 |
| 代码＋解释 | default＋grid | 技术原理、实现对照、关键改动 | 语言代码围栏配对应注释，仅展示关键片段 |
| 公式／方法＋结果 | default＋grid / two-cols | 学术方法、推导结论、实验解释 | KaTeX公式先定义变量，结果保留假设和局限 |
| 行动清单／决策收束 | default | 汇报结尾、推进事项 | 行动、负责人、期限、依赖；未知项标待确认 |

## 相邻页节奏

排版节奏：先按信息关系为每页选择构图，再编排整套节奏。鼓励相邻两页避免相同的主构图；判断的是视觉结构，不是layout字段——连续两页default也可以分别是大数字和时间线，换颜色或交换左右不算真正换版式。生成整套或授权重构时先在内部列出“页码—结论—主构图”，发现相邻重复且内容允许时改选。成组实验、连续同口径比较、逐步推导或用户指定模板可保持相同结构；证据可比性和可读性优先，不为变化牺牲信息表达。整套保持配色、字体、边距、图表语义一致，只变化构图。局部修改不为追求节奏擅自改邻页、增删页或重排顺序。编辑已有页时，仅在确需了解邻页构图且上下文不足时read_page读取相邻页；layout元数据不能代表真实构图，不重复读取已知正文。

示例序列：封面 → 单句结论 → 非对称图文 → 单图表与注释 → 等宽双栏 → 时间线 → 行动清单。此序列只是示范，不要求每份文稿机械套用。三页实验对比使用相同坐标轴、图例位置与版式通常更易比较，应保留一致性。

排版变化应来自主次关系、空间分配与视觉焦点；维持字体、配色与安全边距。不要依赖随机装饰、动画、强行交换左右或频繁变换背景制造变化。

实现依据：本地工具pageSchema与已安装的Slidev布局；[官方布局说明](https://sli.dev/builtin/layouts)。构图分类与节奏规则为本项目的设计建议。
